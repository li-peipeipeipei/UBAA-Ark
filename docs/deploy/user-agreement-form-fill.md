> ✅ **已部署并验证**：GitHub Pages 链接 `https://li-peipeipeipei.github.io/UBAA-HarmonyOS/` 已公开可访问，标题「UBAA 用户协议」、七章齐全、无 `XXXX` 占位符。AGC「协议链接」字段直接填这个地址。

## 第一步：先托管协议网页，拿到公开 HTTPS 链接

任选一种能拿到**公开可访问、无需登录**的 HTTPS 网址的方式（AGC 会校验能否打开）：

### 方式 A：GitHub Pages + Actions 工作流（已配好，推荐）

仓库 `li-peipeipeipei/UBAA-HarmonyOS` 里已经准备好两样东西：
- `site/index.html` —— 协议网页
- `.github/workflows/deploy-pages.yml` —— 部署工作流（只在这两个文件变化时触发）

操作步骤：
1. **提交并推送**这两个文件到 `main` 分支（⚠️ 当前本地 main 有 71 个提交未推送，推送会把它们一起推上去，注意确认）。
   ```
   git add site/index.html .github/workflows/deploy-pages.yml
   git commit -m "Add user agreement page and GitHub Pages workflow"
   git push origin main
   ```
2. 仓库网页 → Settings → Pages → Build and deployment：
   - Source 选 **GitHub Actions**（不是 Deploy from a branch，工作流出托管链接）
3. 推送后自动触发部署，Actions 页签看 `Deploy UBAA Agreement Page` 跑绿；约 1–2 分钟。
4. 拿到链接：`https://li-peipeipeipei.github.io/UBAA-HarmonyOS/`（site/index.html 作为根，不带 `/site/` 后缀）。
5. 浏览器打开验证：显示「UBAA 用户协议」全文、无 `XXXX` 占位符。

> 若推送遇到 TLS/网络问题，记忆里的处理方式：22 端口被封走 `ssh.github.com:443`；HTTPS 中间人只临时 `-c http.sslVerify=false`，别改全局 sslBackend。

### 方式 B：Gitee Pages（国内访问快，需实名）
1. 新建公开仓库，上传 `site/index.html`。
2. 仓库 → 服务 → Gitee Pages，选分支/目录，启动，拿到 `https://xxx.gitee.io/xxx/` 链接。

### 方式 C：任意已有公开 HTTPS 托管
只要链接能公开打开、内容是这份用户协议即可（不能用网盘、需登录的页面）。

> ⚠️ 审核员在国内，GitHub Pages 偶尔访问慢。若担心，优先用能稳定打开的方式；链接填错或打不开会直接驳回。

## 第二步：新建协议弹窗

| 字段 | 填写内容 |
|---|---|
| 协议类型 | `用户协议`（⚠️ 不要选成隐私政策） |
| 协议名称 | `UBAA 用户协议` |
| 语言 | `简体中文 - 默认`（保持） |
| 协议标题 | `UBAA 用户协议` |
| 协议链接 | ⚠️ **必填**——填第一步拿到的公开 HTTPS 网址（如 `https://li-peipeipeipei.github.io/UBAA-HarmonyOS/`） |

> 红字「还有语言属性未完成录入」：名称/标题/链接三项要按语言各填一遍。简体中文填完保存后若仍提示，用「管理语言列表」移除其他语言。

> 📌 备注：如果你在弹窗里看到「使用标准模板 / 在线编辑内容」之类的入口（部分账号可见），也可以像隐私政策那样填模板让华为托管并自动生成 agreement-drcn 链接——那样就不用自己托管了。以你界面实际显示的字段为准。
