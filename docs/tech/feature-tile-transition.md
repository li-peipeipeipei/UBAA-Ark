# 功能块 → 全屏详情：放大 / 缩小转场

> 2026-11-13。沛轩要求：点功能卡片放大到全屏（非线性）、卡片有按压反馈、
> 返回时缩回原卡片、末尾轻微回弹；横屏放大到除侧栏外的全屏、竖屏全屏。

## 0. 技术边界（先说清楚，避免做错方向）

ArkUI 里 **跨页面**的共享元素（iOS 的 hero transition）拿不到对方的节点：

- `NavigationAnimatedTransition` 的 `proxy` 只暴露 `from/to` 的**信息对象**
  （`name/index/param/navDestinationId`），没有节点引用，改不了 transform；
- `geometryTransition` 只在**同一组件树**内生效，跨 `HdsNavDestination` 无效。

所以做不到「卡片这个视图本身长成全屏」。等效做法：

> **记住卡片的中心与尺寸 → 让新页面以「卡片大小的缩放态 + 卡片位置」出现在首帧，
> 再放大到 1。** 视觉上是「从卡片长出来」，本质是整页缩放。

首帧的 `scale = 卡片宽 / 内容区宽`（约 0.18~0.25），`centerX/centerY = 卡片中心`。

## 1. 卡片按压反馈

| 阶段 | 属性 | 曲线 |
| --- | --- | --- |
| 按下（TouchType.Down） | scale 1 → **0.955** | Friction，90ms（跟手，不能有延迟感） |
| 抬起 / 取消 | scale → 1 | springMotion(0.2, 0.6)（轻微过冲） |

不能写成 `onClick`：`onClick` 在抬手才触发，按下的那 100ms 没有任何反馈。

## 2. 入场

```
点击卡片
  ├─ 记录 { cx, cy, w, h }（相对内容区，单位 vp）→ FeatureHero
  ├─ 卡片保持在按压态的 0.955（页面切换瞬间不弹回，视觉连续）
  └─ push 二级页（硬切，转场由页面自己演）

DestShell.aboutToAppear（所有二级页的公共外壳）
  ├─ 有 hero 记录 → 首帧就设 scale=0.18~0.25 / opacity=0.2 / center=(cx, cy)
  ├─ 下一帧 animateTo(springMotion(0.32, 0.86)) → scale=1 / opacity=1
  └─ 动画启动后清掉 hero 记录（只入场一次，返回时不重播）
```

**首帧必须是缩小态**：`@State` 初值直接给缩小值，`aboutToAppear` 里再改。若先渲染 1 再动画到 1，
会闪一帧全尺寸。

**缩放中心**用 `scale({ centerX, centerY })`，坐标与 `FeaturePage` 的 `onAreaChange` 同一坐标系
（相对内容区原点，即横屏已经扣掉侧栏 112vp）。

## 3. 退场（三条路径统一）

| 入口 | 现在的行为 | 需要改成 |
| --- | --- | --- |
| 标题栏返回按钮 / 系统返回 | `AppRouter.back()` → 立即 pop | 先播缩小，再 pop |
| 侧栏「功能」 | `clearStack(2)` → 立即 clear | 先播缩小，再 clear |
| 底栏「功能」 | `onTabBarClick` → `clearStack(2)` | 同上 |

统一机制（`FeatureHero`）：

```
请求退场（带一个「做完之后再执行」的回调）
  → 通知当前 DestShell 播缩小动画（tick 计数器）
  → 动画结束回调 → 执行真正的 pop / clear
  → 通知 FeaturePage 让原卡片回弹一下
```

**为什么必须延迟 pop**：`pop` 一执行页面立即销毁，动画没有播放的载体。

**超时兜底**：动画最长 320ms 未结束也要执行回调，否则用户会卡在页面上（比动画丢失更糟）。

## 4. 回弹

退场动画结束、页面销毁后，原卡片播一次 `1 → 1.035 → 1`
（springMotion(0.18, 0.55)，约 260ms）。

用 `FeatureHero` 记下「刚返回的卡片 index」，该卡片收到后播放一次并复位 ——
不能用全局标记，否则所有卡片一起弹。

## 5. 参数表（集中在一处，方便调）

| 名称 | 值 | 含义 |
| --- | --- | --- |
| `PRESS_SCALE` | 0.955 | 按下缩到多小 |
| `PRESS_DOWN_MS` | 90 | 按下多久到位 |
| `ENTER_SCALE_MIN` | 0.18 | 入场首帧最小缩放（量不到宽度时的兜底） |
| `ENTER_RESPONSE` | 0.32 | 入场弹簧时长（秒） |
| `ENTER_DAMPING` | 0.86 | 入场阻尼（留一点过冲） |
| `EXIT_RESPONSE` | 0.26 | 退场弹簧时长 |
| `EXIT_DAMPING` | 0.9 | 退场阻尼（收得干净，别弹） |
| `BOUNCE_SCALE` | 1.035 | 卡片回弹峰值 |
| `EXIT_TIMEOUT_MS` | 320 | 动画兜底超时 |

## 6. 边界情况

1. **从卡片跳转的深链**（桌面卡片 → 考试页）：没有 hero 记录，不做入场动画，走原硬切 —— 不能报错。
2. **二级页里再跳一级**（博雅 → 课程详情）：第二级没有 hero 记录，正常硬切。
3. **横竖屏切换时**：hero 只作用于「点击那一刻」，转屏不影响。
4. **连点两张卡片**：第二次点击时第一张还在缩放中，`FeatureHero` 以最后写入的为准；
   页面栈只会压一次（`onClick` 有节流）。
5. **退场动画播放期间用户再次进入**：清掉 pending 回调，避免动画结束后又 pop 一次。

## 为什么做不到「完全反向 + 全程不透明 + 精确落点」

这不是参数没调好，而是**打开和关闭时我们控制的不是同一个对象**。

### 1. 两个阶段的性质不同

| | 打开 | 关闭 |
| --- | --- | --- |
| 浮层的角色 | **in**（新插入的组件） | **out**（离场组件） |
| 几何由谁算 | 系统（`geometryTransition`） | 系统（同一套 out 逻辑） |
| 透明度/圆角由谁定 | **我们**（`@State` 驱动） | **系统**（按固定策略渲染） |
| 结果 | 完全可控，能做到「色块长大 + 页面交叉淡入」 | 只能倒放状态，几何与透明度交给系统 |

`geometryTransition` 的 out 阶段是**系统实现**，它做了两件业务侧改不动的事：

- 让离场组件**淡出**（转场视觉连续性，没有开关）；
- 按**终值**渲染离场组件的圆角（不读动画中间值）。

所以收起时「半透明」「圆角跳变」是系统行为，不是我们漏了什么参数。

### 2. 为什么不能绕开 out 过渡、自己缩放

试过三轮，每轮各挂在一个坐标系上：

| 轮次 | 做法 | 结果 | 失败原因 |
| --- | --- | --- | --- |
| 1 | `scale` + `centerX/centerY` 定位 | 缩到屏幕右下 | 布局盒被 `margin({top:-96})` 上移过，center 的坐标系与屏幕坐标差 96 |
| 2 | `position` 定左上角 | 整体右偏 112、下偏 96 | `position` 相对**父容器**，而父容器已被侧栏（112）和标题栏（96）推开 |
| 3 | `translate` + 等比 `scale` | 尺寸「横过来」 | 浮层全屏是横向（≈1.6:1），卡片是竖长（≈0.77:1），等比缩放必然变形 |
| 4 | `translate` + `scaleX/scaleY` + `center 0,0` | 位置基本对，但收缩过程**不透**了 | —— |

第 4 轮其实就是可行解，但它和「完全反向」互斥：它要求我们放弃 `heroOpen = false`，也就放弃了系统那套**精确的**几何插值（改成自己算，落点依赖「浮层原位 = 屏幕 (0,0)」这个假设）。

### 3. 为什么 HDS 让这件事格外难

原生 ArkUI 本来有两条路可走：

1. `Navigation.customNavContentTransition` —— 可以完全接管转场（RedNoteApp「一镜到底」就是用这个）；
2. `geometryTransition` 的 in/out 自定义。

但本项目用的是 HDS 封装的 `HdsNavigation` / `HdsNavDestination`：

- `customNavContentTransition` **不会回调**（加了 Toast 探针，页面进去了但回调没触发）；
- 跨 `HdsNavDestination` 的 `geometryTransition` **不生效**（80ms 抓帧已是全屏，无过渡）。

也就是说 HDS 把转场控制权收走了。我们只能退一步：**不用导航**，在功能页内用浮层渲染详情 —— 这样共享元素才生效（同一棵组件树）。

### 4. 如果要做到「完全反向」，代价是什么

| 方案 | 代价 |
| --- | --- |
| A. 放弃 HdsNavigation，改用原生 `Navigation` + 自绘标题栏 | 24 个二级页全部改造（返回按钮、标题栏、沉浸式、磨砂） |
| B. 自绘页面栈（浮层 + 手写返回栈），几何全自己做 | 需要重写返回手势、系统返回键、页面生命周期 |
| C. 接受系统 out 过渡的淡出 | 收缩时略透、圆角终值跳变（当前方案，位置与尺寸精确） |

**当前选择 C**，理由是：位置和尺寸由系统按卡片真实矩形插值，永远不会偏；而 A/B 的收益只是「收缩时不透、圆角连续」，与工作量不成比例。

## 2026-11-20 修复：云打印跳色 + 平板竖屏圆角跳变

两个现象都出在「卡片」与「转场遮罩」之间的**数据不同源**上，与动画参数无关。

### 1. 云打印放大 / 缩小时颜色不一致

`FeatureItem` 里有三个颜色字段，转场只能读 hex、卡片只能读 Resource，靠人保证一致：

| 字段 | 谁在用 |
| --- | --- |
| `color: Resource` | 卡片渲染（`FeatureTile` 的色层） |
| `colorValue: string` | 转场遮罩的浅色基础色 |
| `colorDark: string` | 转场遮罩的深色基础色 |

11 个功能块里只有云打印不匹配：`color` 写的是 `AppColor.brand`（蓝 `#1976D2`），
`colorValue` 是青色 `#00897B` —— 卡片是蓝的，展开动画是青的。

修法：新增 `accent_teal` 资源（浅 `#00897B` / 深 `#26A69A`）+ `AppColor.accentTeal`，
云打印的 `color` 改用它。

> **新增功能块时必须核对三个字段同源**，否则又是一次跳色。

### 2. 平板竖屏收起落地时圆角跳变

根因是 `FeatureTile.radius` **没有 `@Prop` 装饰器**。

`radius` 由父级按「块宽 × 0.16」算好传入，而块宽会随列数变化。普通成员只在
初始化时赋值一次，父级后续更新既不写入也不触发重绘 —— 卡片的圆角永远停在兜底值 28，
而父级上报给转场遮罩的是实测值。

为什么只有平板竖屏看得出来：断点兜底列数与实测列数差得最远。

| 形态 | 断点 | 兜底列数 | 实测列数 | 实测圆角 | 与卡片(28) 的差 |
| --- | --- | --- | --- | --- | --- |
| 平板横屏 | lg | 6 | 5 | 28 | **0**（所以没问题） |
| 手机竖屏 | sm | 4 | 2~3 | 26~31 | 1~3（不易察觉） |
| 平板竖屏 | md | 6 | 4 | 29~33 | 5 以上（可见） |

遮罩收缩终点用实测圆角、落地后卡片露出的是 28 —— 那一帧的跳变就是用户看到的「突变」。

修法两处：
1. `radius` 改 `@Prop`，父级 `tileRadius` 变化能真正刷新卡片；
2. `onBounds` 增加 `radius` 参数，由卡片上报**自己正在渲染的**圆角，
   `liveCard.radius` 与 `cardRect().radius` 优先用它 —— 无论谁先更新，
   遮罩始终与卡片同值。

第 2 条是防御性的：即使将来又出现「父级算的值和孩子渲染的值不同步」，
转场也不会再跳到另一个圆角上。

## 2026-11-22 修复：展开页 → 页内二级页 → 返回后，功能块一直隐藏

**现象**：功能页点「博雅课程」→ 博雅首页 → 「我的课程」→ 连按返回回到功能页，
「博雅课程」这个块**消失**，但位置上仍能点进去；再进出一次才恢复。

**根因**：原卡片的重新显示**只有一个出口** —— `finishShrink()` 里的
`NavHero.notifyTileShow()`。而 `FeaturePage` 的卡片在 `open()` 后 30ms 就被置为
`heroHideTile = true`（视觉隐藏、hitTest 仍在，所以"空位能点"）。

只要这次 POP 没走「缩回卡片」这条路，就再没有任何地方发 SHOW：

- `heroTransition` 的 POP 分支在 `!NavHero.isTopHero()` 时直接 `return undefined`
  （交给系统默认滑出）→ 没有收缩动画 → `finishShrink()` 不执行；
- 「展开页 → 二级页 → 返回功能页」这条路径上，`shells` 的顺序取决于二级页
  `aboutToDisappear` 的时序；展开页的内容也可能被系统回收，导致 `KEY_HERO_CLOSE`
  的 `@Watch` 收不到 → `startShrink()` 从不执行。

**修法（两条兜底，都在 `MainPage.heroTransition`）**：

1. POP 且 `!isTopHero()`：延时 60ms 检查 `featureStack.size() === 0`（已回到功能页根），
   是就 `notifyTileShow()`。**判据用栈深，不用 `to.name`** —— 根页面上 `NavContentInfo.name`
   填什么没有文档保证，栈深是确定的；延时是因为回调里栈还没 pop 完。
2. POP 且接管转场：`shrinkDone` 先复位，再挂 1200ms guard —— 超时若收缩仍未完成，
   强制 `finishShrink()`（放开卡片 + `finishTransition()` 释放 proxy，避免卡在「转场中」）。
   guard 带 `popGuardToken` 轮次号防串轮；PUSH 接管时递增 token 作废旧 guard，
   否则上一轮的兜底会把新一轮的 proxy 提前放掉（画面无动画直接切）。

⚠️ **不要图省事改成「展开完成后就把卡片显示出来」**：收缩全程真卡片必须隐藏，
否则 0.86 半透明的彩色层会透出底下那张同名卡片（见前文「退场」）。

## HDS 二级页转场：外壳底色必须铺在「内容树」上

横屏进任意二级页（29 个共用 `DestShell`），末帧曾在「左侧导航栏右边 ↔ 新页面左缘」之间
露出旧页面一条、闪一下消失。竖屏不可见 —— 横屏内容区被 `padding-left = sideNavWidth`
推到侧栏右边，那条透明缝正好有了参照物。

根因不是侧栏半透明（试过给侧栏垫底，无效）：`HdsNavDestination.backgroundColor` 铺在
**外壳**上，而转场系统渲染并平移的是 destination 的**内容树**；底色不跟着平移，新页面
未落位时左缘那段就是透明的，落位后底色才生效。

修法：`DestShell` 最外层 `Column` 铺 `AppColor.pageBackground`，随内容一起平移，任何帧不透。
与「HdsNavDestination 不能留 backgroundColor(Transparent)」（标题栏材质采样）是**两条独立**的坑：
前者管内容的平移透明，后者管标题栏的采样源，两处都要铺。
